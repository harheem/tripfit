# 07 — 채팅방 안 경험 다시 설계: TripFit 벤토 디자인 + 메신저 문법

너는 `vooy-mcp/` 폴더에서 일한다. 첨부 `current_card.jpg`가 지금 inline 대화 카드다(흰 카드, 06에서 만든 것). 사용자 피드백 두 가지:

1. **카톡 단톡방이나 인스타 DM 안에서 보인다고 가정하고 경험을 다시 고려할 것**
2. **디자인은 원래 TripFit처럼** — 흰 범용 카드가 아니라 TripFit의 네이비 바탕 파스텔 벤토

원래 TripFit 디자인 원본(읽기 전용, 토큰·모션 코드를 그대로 가져와도 됨): `../tripfit/SCREENS.md` §3(비주얼·모션 시스템), `../tripfit/web/index.html`(토큰 `--navy #0E2A3A, --navy-2 #173A4C, --cream #F3F1EA, --lime #D6F23B, --mint #BDEFDB, --pink #FFCCE5, --sky #8EC5EE, --peach #F8D5BC, --butter #F4E58E, --leaf #A8E2C3, --lilac #CBBDFF, --red #FF5B4A`, 숫자 폰트 Inter Tight 계열 tabular, 한글 Pretendard 계열, CSS `linear()` 실제 스프링, 숫자 자리별 롤링, 다이내믹 아일랜드). 외부 폰트는 못 쓰니 시스템 폰트로 근사한다.

## 1. 채팅방이라는 맥락 (설계 전제)

| 맥락 | 설계에 주는 뜻 |
|---|---|
| 봇 말풍선·카드는 화면 폭의 70~75% (390px 폰에서 **약 270~290px**) | inline 카드 기준 폭 **280px**. 260~340px에서 깨지지 않게. 360px 기준으로 만든 레이아웃은 버린다 |
| 보이는 대화 영역은 폰 높이의 60~70% | 카드 높이 **목표 300~340px, 최대 380px**. 카드 하나가 화면을 다 덮으면 앞뒤 대화가 끊긴다 |
| 카톡 단톡방: 옅은 회청색 배경, 흰 말풍선 / 인스타 DM: 다크 모드가 많고 검정 배경 | 카드 자체가 네이비 면이라 두 배경 모두에서 선다. 다크 배경에선 1px `rgba(255,255,255,.08)` 외곽선으로 경계 |
| 단톡방에서 위젯 조작은 **조작한 사람 화면에서만** 바뀐다 | 모두에게 영향을 주는 결정(이 안으로 정하기, 양보)은 조용한 `tools/call` 대신 **대화에 메시지로 남긴다**: `ui/message`로 사용자의 말 "균형안으로 하자"를 대화창에 보내고 vooy가 이어받는다. `ui/message`가 거절되면 그때만 `tools/call` |
| 카톡 봇 메시지 아래 **빠른 답장 버튼**(알약)에 사람들이 익숙하다 | 카드 맨 아래 빠른 답장 알약 2~3개: "이 안으로 정하기" / "다른 안 보기" / "크게 보기". 알약 높이 36px, 가로 스크롤 금지(넘치면 2개만) |
| 새 계산 결과는 **새 메시지의 새 카드**로 뜨고 예전 카드는 위로 밀려 올라간다 | 각 카드에 "몇 번째 계산인지"(rev)를 작게 표시. 예: "2차 계산". 예전 카드를 바꿀 방법은 없으므로 카드가 스스로 완결돼야 한다 |
| 알림·미리보기엔 텍스트만 보인다 | 서버 `content` 텍스트의 **첫 줄**을 사람 말로: 예 "다들 OK인 코스 3안 — 민지 100 · 지훈 100 · 서연 100". 지금 첫 줄 "3안 · 계산 3960ms · 후보 순서 조합 약 6,337,216개"는 알림으로 쓸모가 없다. `hapui/text.py`의 첫 줄만 바꾸고 나머지 줄 규칙(12줄 이내, 따옴표, 데이터 라벨, 보드 링크)은 유지. 기존 테스트가 첫 줄에 의존하면 맞춰 고쳐라 |
| 엄지로 스크롤하다 오탭이 잦다 | 탭 타깃 40px 이상, 카드 안 가로 스와이프·드래그 금지, 슬라이더는 inline에 두지 않는다 |

## 2. inline 카드 — TripFit 벤토 (기준 폭 280px)

카드 = 네이비(`--navy`) 면, 라운드 22px, 안쪽 4px 패딩, 블록 사이 4px 네이비 틈(벤토 모자이크). 블록은 단색 파스텔, 라운드 16px. 그라데이션·그림자 금지(외곽선만).

1. **아일랜드 줄**(네이비 위, 블록 아님): 왼쪽 라임 원 18px + "TripFit" 12px 크림색, 오른쪽 작은 검정 알약(다이내믹 아일랜드 축소판) "3안 · 3.9초" 11px. 계산 중이면 알약이 점 3개로
2. **라임 헤드라인 블록**(가로 전체): 위 작은 줄 "성수 · 13–18시 · 3명" 11px 네이비 70%, 큰 줄 상태 문장 18px/700 "다들 OK인 코스" / "지훈이 조금 양보" / "이대로는 안 돼요"(이때 블록 색 `--red`, 글자 네이비) / "다시 계산했어요", 오른쪽 아래에 **최소 만족도 큰 숫자** 40px Inter-tabular "100" + "%" 14px (rolling digits)
3. **사람 타일 줄**: 사람 수만큼 가로 균등 블록(3명이면 3칸, 4명 이상은 3칸 + "+N" 칸). 각 블록 = 사람 색(pink/sky/peach/butter/mint/lilac 순), 이름 11px/600, % 24px tabular, 아래 얇은 진척선(블록 안 네이비 15% 트랙 + 네이비 채움 `scaleX`). 양보한 사람은 블록 오른쪽 위 작은 네이비 알약 "양보". `pct:null`이면 "—"와 "조건 없음"
4. **안 탭**(네이비 위 알약 3개, 블록 아님): 선택 = 라임 면 네이비 글자, 나머지 = 투명 + 크림 테두리 1px. 높이 30px, 글자 12px/600. 이름 길면 말줄임
5. **코스 블록**(크림 `--cream` 면): 최대 3곳 "13:02  성수역 소품샵 골목"(시각 tabular 11px 네이비 60% + 장소 13px/600 말줄임), 장소 앞 6px 카테고리 색 점(전시 lilac·카페 peach·식당 pink·소품샵 sky·골목 butter·공원 leaf·체험 mint), 넘치면 "+2곳 · 도보 1.0km" 한 줄
6. **바뀐 점**(diff 있을 때만, 코스 블록 맨 위 한 줄): "+ 어니언 성수"(leaf 알약) "− 연무장길 골목"(취소선)
7. **빠른 답장 줄**(네이비 위): 알약 "이 안으로 정하기"(라임 면) / "크게 보기 ↗"(크림 테두리). undo 가능하면 "되돌리기"를 세 번째 대신 넣고 크게 보기는 아이콘 버튼으로
8. **출처 한 줄**(네이비 위 10px 크림 60%): "실제 계산 · 장소 샘플(성수) · 도보 추정 · 2차 계산"

**infeasible**: 헤드라인 블록이 빨강, 사람 타일 대신 **양보 카드 블록** 최대 2개(butter 면): "지훈 · 걷기 1km 풀면 → 모두 100%" + 오른쪽 작은 네이비 알약 "이걸로". 버튼은 `ui/message`로 "지훈 걷기 조건은 양보할게"를 대화에 보낸다(거절 시 그 선택지의 `apply`로 `tools/call`).

**다크/라이트**: 카드는 같은 네이비. 호스트 theme은 바깥 외곽선과 문서 배경(투명 유지)에만 영향.

## 3. 모션 (원래 TripFit 모션을 채팅 크기에 맞게)

- 첫 등장: 카드 전체가 아래에서 튀어 오름(TripFit 스프링, 280ms 이내) → 블록 4개가 40ms 간격으로 따라 들어옴(전체 450ms 안). 최소 만족도 숫자 자리별 롤링
- 새 결과/안 전환: 사람 타일 % 롤링 + 진척선 스프링, 코스 블록 FLIP(들어온 곳 leaf 하이라이트 600ms, 빠진 곳 기울며 왼쪽 퇴장)
- 아일랜드 알약: 계산 중 → 결과 문장으로 펼쳐짐(폭 스프링)
- `prefers-reduced-motion` 즉시. `transform/opacity`만
