## 0. 결론 먼저

| | 내용 |
|---|---|
| **추천** | **① 합의저울** — 단톡방에서 각자 한 말을 체크리스트로 바꾸고, 솔버가 "다들 OK"인 안 3개를 계산해 MCP App 카드로 띄우는 서버. 저울을 밀거나 "이건 양보할게"를 누르면 그 자리에서 다시 계산한다 |
| **범위(확정)** | **친구 모임 나들이 반나절 코스**(3명 이상 × 여러 곳 순서 × 시간 제약). 회식 장소 1곳 같은 단순 합의는 범위 밖 → §4.1 |
| 한 줄 | **vooy에겐 손(캐치테이블·요기요·캘린더·마이리얼트립 연동)이 있다. 이 서버는 저울을 준다.** |
| 이유 | (1) vooy는 메신저 에이전트이고 단톡방에서도 돈다 → "여럿이 정하기"가 vooy의 본래 자리다. (2) 지난 vooy 해커톤 참가작은 대부분 데이터를 가져오는 MCP였다. 계산을 책임지는 MCP는 없었다. (3) `tripfit/solver`가 이미 돌아간다(파레토 대안, 최대-최소 균형안, `what_if_add`, `reoptimize`, `diagnose`). 4시간 대부분을 MCP 래핑과 MCP App 화면에 쓸 수 있다 |
| 트랙 조건 [공식] | 도구 1개 이상인 **원격 MCP 서버(https)** + **레시피**(언제 그 도구를 쓸지 적은 지침과 예시 대화). 완료 기준은 "메신저에서 말을 걸면 도구가 호출되고 결과가 대화로 돌아옴". 의도 파악과 도구 선택은 vooy가 한다 → 합의저울은 `propose_plans` 하나만 끝까지 돌아도 조건 충족 |
| MCP Apps | 운영팀 안내에도 위젯 렌더링 언급이 없다(**[미확인]**). 그래서 **텍스트가 본편, 위젯은 보너스**로 순서를 바꿨다: ① `structuredContent` + 대화로 바로 읽히는 텍스트 결과(완료 기준을 이것만으로 채움) → ② 같은 결과를 `https://…/b/{id}` 링크 보드로(폰 브라우저에서 저울 조작) → ③ vooy가 `ui://`를 그리면 대화 안 위젯 |
| 오늘 첫 확인 | ① vooy 베타 계정 접근 방법(운영팀 "확인 중") ② 위젯(`ui://`, `text/html;profile=mcp-app`) 렌더링 여부 ③ 단톡방에서 사용자 지정 MCP 호출 가능 여부. ②③의 답으로 §6 동선을 고른다 |

### ① 합의저울 — "다들 OK" 계산기 (추천)

**한 줄**: 단톡방에서 각자 한 문장씩 말하면, 누가 얼마나 양보하는지 숫자로 보이는 "다들 OK"인 안 3개를 계산한다. 여행 반나절 코스, 회식 장소, 주말 약속처럼 **후보 + 시간 + 여러 사람의 조건**이면 다 된다.

**vooy 안에서의 장면**

1. 단톡방: 민지 "난 전시 하나는 꼭" / 지훈 "많이 걷기 싫어, 3시 전엔 밥" / 서연 "2만원 넘으면 안 돼" / "@vooy 성수에서 오후에 뭐 할지 정해줘"
2. vooy가 후보를 모은다. vooy 기존 연동(캐치테이블·카카오맵·마이리얼트립)을 쓰거나, 우리 서버의 `find_candidates`(마이리얼트립 공개 MCP 실호출 + 샘플 장소)를 부른다
3. vooy가 각자의 말을 조건으로 바꿔 `propose_plans`를 호출한다(말→조건은 LLM, 숫자는 서버)
4. 돌아오는 것: 안 3개(민지 우선 / 균형 / 지훈 우선), 각 안마다 사람별 체크리스트 %, 동선·시간표, "가능한 조합 N가지 → 3개". MCP App이 뜨면 벤토 카드 보드, 안 뜨면 vooy가 텍스트 카드로 요약 + 보드 링크
5. 서연 "난 예산 좀 넘어도 돼" → `adjust_plan(yield)` → 막대가 바로 바뀜
6. 조건이 서로 안 맞으면 `explain_infeasible` → "지훈이 도보 1.2km→1.6km를 받아주거나, 민지가 전시를 빼면 OK"
7. 정해지면 vooy가 원래 가진 손(캐치테이블 예약, 캘린더 등록)으로 넘긴다. 결제·예약은 vooy의 사용자 확인 흐름을 따른다

**MCP 도구 초안 (5개)**

| 도구 | 입력(요약) | 출력(요약) | UI |
|---|---|---|---|
| `find_candidates` | `area`(예: "성수"), `kinds[]`(food/cafe/exhibit/experience…), `when` | `candidates[]`: `id,name,lat,lng,tags[],price,open,close,stay_min,rating,reviews,branches,crowd,source(live|sample)` | 없음 |
| `propose_plans` | `members[]`: `{name, wants[]: {text, kind: must|want|avoid, strength: 강|보통|약, match: {tags?, place_id?, max_walk_m?, max_price?, before?, after?}}}`, `candidates[]`(위 형식, 생략하면 `area`로 자동), `window{start,end}`, `start_point?` | `problem_id`, `search_space`, `plans[]`: `{plan_id, label, stops[{name,arrive,leave,walk_m}], per_person[{name, pct, items[{text,fill}]}], min_pct, cost}`, `balanced_plan_id`, `summary_text` | `ui://hapui/board` |
| `adjust_plan` | `problem_id`, 그리고 `{weights{name:0..1}}` 또는 `{yield{name,want_text}}` 또는 `{add|remove place_id}` | 새 `plans[]` + `diff`(누가 몇 %p 바뀌었나, 무엇이 빠졌나) | 같은 보드 갱신 |
| `explain_infeasible` | `problem_id` | `concessions[]`: `{who, give_up, then_pct}` 최소 1개·2개 조합 | 같은 보드의 "양보 카드" |
| `replan_now` | `problem_id`, `plan_id`, `now`, `done_ids[]`, `fixed_ids[]`, `changes{crowd?}` | 고정한 약속은 지키고 나머지만 바뀐 안 + diff | 같은 보드 |

- 서버는 `problem_id`로 문제를 메모리에 들고 있어서, 위젯 안 슬라이더·버튼이 `adjust_plan`을 다시 부를 수 있다
- 모든 도구 결과에 `structuredContent` + 3~5줄 `summary_text` + 보드 링크 `https://<host>/b/{problem_id}`를 같이 넣는다(§1.3 폴백 원칙)
- 도구 설명에 한국어 예문 5개씩(vooy 도구 검색 대응)

**남들이 안 할 이유 / 쓸모**

- 지난 vooy 해커톤 참가작(개인정보 유출 감시, 행정 절차 근거 조회, AWS 파이프라인, 퇴근 후 비서, 호들갑 알림, 벌칙 메뉴 추첨)은 거의 **데이터를 가져오거나 행동을 대신하는 MCP**였다. **계산을 책임지는 MCP**는 없었다
- LLM은 "4명 × 조건 10개 × 후보 30곳 × 시간창"을 머리로 풀면 그럴듯하게 틀린다. 그 부분을 MIP 솔버가 맡고, 각 숫자를 표로 되짚을 수 있다
- 단톡방에서 정하기는 vooy가 이미 있는 자리이고, 끝에 "예약"으로 이어진다 → vooy의 기존 연동을 더 쓰게 만드는 MCP

**1분 데모의 와우**: 세 명의 말이 들어가면 카드에 "가능한 조합 77만 가지 → 3안"이 찍히고, 사람별 막대 3개가 뜬다. 저울을 밀면 한 사람 막대가 오르고 다른 사람 막대가 내려간다. "전시 양보할게"를 누르면 1초 안에 동선이 바뀐다.

**실제로 돌아가는 범위 / 목업 범위**

| 실제 | 목업·샘플(화면에 표시) |
|---|---|
| 솔버 계산 전부(파레토·균형·양보·재계산) | 혼잡도 값(샘플, 실시간 도시데이터는 스트레치) |
| 마이리얼트립 공개 MCP 후보 조회(인증 없음) | 성수 식당·카페 일부 좌표·영업시간(`tripfit/solver/sample_seongsu.py` 샘플) |
| vooy 사용자 지정 MCP 연결과 실제 도구 호출 | 예약 확정(vooy의 캐치테이블 연동이 하는 일이고, 무대에서는 확인 화면 직전까지만) |
| MCP App HTML 위젯(호스트가 그리면) / 같은 HTML 웹 링크 | vooy가 위젯을 못 그리면 위젯은 링크로만 보여 줌 |

### ② 양보처방 — "안 되는데, 뭘 빼면 돼?"

- **한 줄**: 바라는 게 동시에 안 되면 LLM은 아무거나 빼고 "이렇게 해 봤어요"라고 한다. 이 서버는 **빼야 할 최소 조건 조합**과 각 선택지의 대가를 계산해 처방전처럼 돌려준다
- **장면**: "토요일 3시간, 성수에서 전시+점심+카페, 걷기 1km 이하" → `check_feasible` → 불가능 → `prescribe` → "① 도보 1.4km 허용 ② 카페 빼기 ③ 30분 연장, 각각 이렇게 바뀜"
- **도구**: `check_feasible(problem) → {feasible, plan?}`, `prescribe(problem) → concessions[{give_up[], cost_text, resulting_plan}]`, `apply_concession(problem_id, idx)`
- **MCP Apps**: 양보 카드 3장, 탭하면 결과 동선 미리보기
- **새로움/쓸모**: 높음. "불가능"을 설명하는 에이전트 도구는 드물다. 다만 혼자 쓰면 장면이 작다 → **①에 기능으로 넣는 게 낫다**(`explain_infeasible`)
- **와우**: 중. "안 돼요" 대신 "이 중 하나만 고르세요"가 뜨는 순간
- **실제/목업**: `diagnose` 실동작. 해제 대상이 도보·필수 방문·카테고리/태그 최소 개수뿐이라, 예산·시간 연장은 새로 넣어야 함(목업 아님, 추가 구현)
- **4시간**: 쉬움(2시간)
- **리스크**: 단독 피치로는 "기능 하나"로 보일 수 있음

### ③ 하루 테트리스 — 캘린더 빈칸에 할 일 끼워 넣기

- **한 줄**: 오늘 캘린더 사이 빈칸에 "은행, 택배, 운동, 장보기"를 영업시간·이동시간 지켜 끼워 넣고, 회의가 밀리면 약속은 지킨 채 나머지만 다시 짠다
- **장면**: "오늘 이거 다 할 수 있어?" → vooy가 구글 캘린더 일정을 읽어 넘김 → `pack_day(events[], todos[], home)` → 타임라인 + "택배는 못 넣음, 내일로" → "3시 회의 4시로 밀렸어" → `repack(now, moved_event)`
- **도구**: `pack_day`, `what_if_add(todo)`(넣으면 뭐가 빠지나), `repack`
- **MCP Apps**: 세로 타임라인, 할 일 블록을 끌어 고정
- **새로움/쓸모**: 중. 개인 일정 최적화는 기존 앱이 많다. vooy의 캘린더 연동과 붙는 점은 좋다
- **와우**: 중. 일정이 밀리면 블록이 우르르 재배치되는 장면
- **실제/목업**: 솔버 실동작. 캘린더 일정은 vooy가 넘겨줘야 함(넘겨줄지 미확인) → 무대용 일정은 샘플일 가능성
- **4시간**: 빠듯함. 장소 후보 대신 "할 일" 모델로 바꾸는 작업이 생김
- **리스크**: vooy↔캘린더↔우리 MCP 연결 체인이 길다

### ④ 계산 영수증 — "왜 이 집?"에 숫자로 답하기

- **한 줄**: vooy가 무언가를 추천할 때 후보들을 공개 표(Q = 0.4 고유성 + 0.3 베이지안 평판 + 0.3 혼잡)로 다시 채점해, 숫자 하나하나의 출처가 적힌 영수증을 준다
- **장면**: "성수 카페 추천" → vooy가 후보 5곳 → `score_receipt(candidates[], weights?)` → "평점 4.8(리뷰 12개)은 베이지안 보정으로 4.3, 지점 1곳이라 고유성 1.0…"
- **도구**: `score_receipt`, `compare(a,b)`, `weights_table()`(공개 기본값)
- **MCP Apps**: 영수증 카드, 가중치 슬라이더
- **새로움/쓸모**: 중. 환각 방지 메시지는 좋지만 체감이 약하다
- **와우**: 낮음. 리뷰 12개짜리 4.8이 리뷰 3천 개짜리 4.5에 밀리는 순간 정도
- **실제/목업**: 계산 실동작. 평점·리뷰 수는 MRT 실데이터 가능, 혼잡은 샘플
- **4시간**: 쉬움
- **리스크**: 피치가 설명조가 됨

### ⑤ 공평 N빵 — 방·비용·당번을 질투 없이 나누기

- **한 줄**: 여행 숙소 방 배정과 비용, MT 당번, 집안일을 각자 선호를 받아 "아무도 남의 몫을 더 탐내지 않게" 나눈다(배정 MIP + 가격 조정)
- **장면**: "방 3개(큰방·작은방·거실) 우리 넷이 어떻게 나눠?" → 각자 방별 선호 금액 → `fair_split` → 배정 + 1인당 금액 + "아무도 바꾸고 싶지 않음" 검증표
- **도구**: `fair_split(people[], items[], prefs)`, `swap_check(a,b)`, `settle()`(송금 최소화)
- **MCP Apps**: 배정 보드, 사람 카드를 드래그하면 질투 표시
- **새로움/쓸모**: 중. 정산 앱은 많고, 지난 vooy 해커톤에 "메뉴 배정" 참가작(ttavara-sip)이 있어 겹쳐 보일 수 있음
- **와우**: 중
- **실제/목업**: 계산 실동작, 데이터는 사용자 입력이라 목업 없음
- **4시간**: 가능하지만 tripfit 자산 재사용률이 낮음(새 모델)
- **리스크**: "N빵 계산기"로 작게 보임. 송금은 하지 않는다(금융 실행은 범위 밖)

## 4. 추천: ① 합의저울 (②를 기능으로 흡수)

1. **vooy와 맞는 자리**: vooy는 메신저 에이전트이고 단톡방에서도 돈다. 여럿이 정하는 일은 메신저에서 가장 자주 막히는 일이고, 끝이 예약·캘린더라 vooy의 기존 손과 바로 이어진다
2. **vooy에 없는 것**: vooy는 도구 200개로 "가져오고 실행하는" 능력은 많다. 여러 사람의 조건을 동시에 만족시키는 **계산 기관**은 없다. 지난 vooy 해커톤 참가작에도 없었다
3. **텍스트만으로도 서고, 화면이 붙으면 더 산다**: 완료 기준(결과가 대화로 돌아옴)은 3안 시간표와 사람별 %만으로 채운다. 저울과 양보 버튼은 링크 보드로 보여 주고, vooy가 MCP Apps를 그리면 같은 화면이 대화 안에 뜬다. 화면은 결과를 꾸미는 용도가 아니라 **다시 계산을 부르는 조작면**이다
4. **실제로 돈다**: 솔버·테스트가 이미 있어 4시간 대부분을 연결과 화면에 쓴다
5. **정직하게 말할 수 있다**: 어떤 숫자가 실호출이고 어떤 게 샘플인지 화면에 라벨로 붙인다

이름 후보: 합의저울 / 다들OK / 한판합의. 문서에서는 "합의저울"로 부른다.

## 4.1 범위를 좁힌다: 모임 나들이 코스 (확정, 2026-11-07)

"아무 합의나"로 팔지 않는다. 합의저울이 vooy 혼자보다 확실히 나은 곳은 **3명 이상 × 여러 곳을 순서대로 × 시간 제약**이 겹칠 때다. 그래서 피치와 데모는 **"친구 모임 나들이 반나절 코스"** 하나로 간다.

### 누가, 언제 쓰나

| 쓰임새 | 장면 | 무대에서 |
|---|---|---|
| **친구 모임 나들이** (주력) | 토요일 오후, 친구 3명이 성수에서 반나절. 단톡방에서 각자 한 줄씩 말하고 vooy를 부름 | 데모 본편 |
| 나들이 중 다시 짜기 | 카페에서 20분 더 있었거나 전시가 붐빔 → "공방 예약은 지키고 나머지만 다시" | 데모 마지막 10초(시간 되면) |
| 가족 나들이 | 아이·어르신 조건(걷기 상한, 낮잠·식사 시간)이 들어간 경우 | 피치에서 한 줄 언급만 |

범위 밖: 회식 장소 1곳 고르기, 날짜 투표, 정산·배정. vooy 혼자서도 되거나 다른 문제다.

### 어떤 말이 조건이 되나 (말 → 조건 사전)

| 구분 | 예시 | 서버가 받는 조건 | 화면 표시 |
|---|---|---|---|
| 되는 말 | "전시 하나는 꼭" | `must`, `tags: [exhibit]`, 최소 1곳 | 체크리스트 항목 |
| | "많이 안 걷고 싶어" | `max_walk_m` (강=1.5km, 보통=2.5km 공개 기본값) | 〃 |
| | "3시 전엔 밥" | `tags: [food]`, `before: 15:00` | 〃 |
| | "2만원 넘으면 안 돼" | `max_price: 20000` (1인 합계) | 〃 |
| | "6시엔 가야 해" | `window.end: 18:00` | 〃 |
| | "거긴 지난주에 갔어" | `avoid place_id` | 〃 |
| 애매한 말 | "분위기 좋은 데", "힙한 데" | 평점·태그로 근사(`vibe → tags: [cafe, popup]` 사전) | "근사치" 라벨 |
| 안 되는 말 | "재밌게 놀자", 데이터에 없는 기준(주차 등) | 계산에서 제외 | "확인할 수 없음" 라벨 + vooy가 그렇게 말함 |

말을 조건으로 바꾸는 건 vooy의 LLM이 한다. 서버는 받은 조건만 계산하고, 바꾸지 못한 말은 숨기지 않고 "확인할 수 없음"으로 돌려준다.

단톡방에 쌓인 잡담을 vooy가 읽어서 조건을 뽑는지는 **[미확인]**. 데모는 "vooy를 부르는 메시지에 각자 한 줄씩"으로 짠다.

### 무대 시나리오 (친구 3명, 성수, 토요일 13:00–18:00)

| 단계 | 단톡방 | 호출 | 돌아오는 것 |
|---|---|---|---|
| 1 | 민지 "전시 하나는 꼭" / 지훈 "많이 걷기 싫어, 3시 전엔 밥" / 서연 "카페에서 좀 쉬고 싶어, 2만원 안으로" / "@vooy 오후 코스 짜줘" | `propose_plans` | 3안(민지 우선 / 균형 / 지훈 우선). 안마다 시간표, 도보 거리, 사람별 체크리스트 % |
| 2 | 서연 "난 예산 좀 넘어도 돼" | `adjust_plan(yield)` | 막대 3개가 움직이고 diff("카페 추가, 지훈 −3%p") |
| 3 | 민지 "디뮤지엄 꼭 + 공방 2시도" | `propose_plans` → 불가능 → `explain_infeasible` | 양보 선택지 카드 3~4장("도보 상한을 늘리고 공방을 빼면 가능" 등) |
| 4 | "균형안으로 하자" | (vooy 기존 연동) | 첫 식당 예약 확인 화면 직전에서 멈춤 |

**참고 실측값 (오늘 `tripfit/solver/demo.py` 실행, 2인·샘플 장소)**: 3안 계산 1.34초. 지민 우선 100%/65%, 서연 우선 79%/83%, 균형 79%/80%. "가죽공방 16시 추가"는 소품샵·할아버지공장·연무장길이 빠지고 서연 −4.8%p. 조건 충돌 시 양보 선택지 4개. **3인 시나리오 수치는 구현 후 다시 잰다.**

### vooy 혼자 할 때와 비교 (피치의 근거)

| vooy 혼자 | 합의저울을 붙이면 |
|---|---|
| 그럴듯한 코스 하나. 영업시간·이동시간이 맞는다는 보장 없음 | 도착·출발 시각이 전부 계산으로 맞음 |
| 누구 말이 빠졌는지 안 보임 | 사람별 %와 빠진 항목이 보임 |
| 안 되면 조용히 하나 뺌 | 무엇을 양보하면 되는지 선택지를 줌 |
| 중간에 바뀌면 처음부터 | 예약은 지키고 나머지만 |
| 숫자 출처 없음 | 공개 점수표로 되짚을 수 있음 |

> (8–20초) vooy는 이미 예약도 하고 주문도 합니다. 손은 있어요. 그런데 넷이 각자 다른 말을 하면 누구 말을 얼마나 들어줄지 정하는 **저울**이 없습니다. 그래서 MCP 서버로 하나 만들어 붙였습니다. 주소 한 줄이면 됩니다.
>
> (20–42초) [시연] 셋이 한 문장씩 말하고 vooy를 부르면, 가능한 조합 77만 가지 중에 다들 OK인 안 3개가 나옵니다. 각자 한 말이 몇 % 지켜졌는지 보이고, 저울을 밀면 누가 얼마나 양보하는지가 바뀝니다. "전시는 양보할게"를 누르면 1초 만에 다시 계산합니다.
>
> (42–55초) 원칙은 하나입니다. LLM은 말을 조건으로 바꾸기만 하고, 숫자는 솔버와 공개된 표에서 나옵니다. 그래서 이 숫자는 왜 나왔는지 되짚을 수 있어요.
>
> (55–60초) 정해지면 그다음은 vooy가 원래 잘하는 예약입니다. 합의저울이었습니다.

수치("77만 가지", "1초")는 무대 직전 실측값으로 바꾼다.

## 6. 데모 동선

### 공통 사전 준비 (16:30까지)

- 서버: `ngrok http <port>`(띄운 뒤 재실행 금지) → `https://<ngrok 주소>/mcp`
- vooy: 서비스 연결 화면에 https 주소 등록 → 도구 목록 인식 확인 → **이 화면을 캡처해 둔다**(연결 장면용)
- 레시피: Recipe Studio에 지침 + 예시 대화(§4.1 무대 시나리오) 등록, Studio 대화로 1회 끝까지 테스트
- 단톡방: 팀원 3명 계정 + vooy(단톡방 호출이 안 되면 1:1 대화)
- 폴백: 같은 시나리오 화면 녹화 30초

**기본은 동선 B**(텍스트 + 링크 보드)다. 위젯 렌더링이 현장에서 확인되면 동선 A로 바꾼다.

### 동선 A — vooy가 MCP App을 그리는 경우 (보너스)

| 초 | 화면 | 말 |
|---|---|---|
| 0–8 | 단톡방, 세 명의 말이 이미 올라와 있음 | 공감 오프닝 |
| 8–20 | vooy 설정 › 사용자 지정 MCP › 우리 URL + 도구 5개 목록(실화면 또는 캡처) | "주소 한 줄로 붙였습니다" |
| 20–30 | "@vooy 오후에 뭐 할지 정해줘" → 대화 안에 보드 위젯(3안, 사람별 막대) | 77만 → 3 |
| 30–42 | 위젯에서 저울을 밀고 "전시 양보" 탭 → 막대와 동선이 바뀜 | 양보가 숫자로 |
| 42–55 | 하단 라벨 "솔버 계산: 실제 / 혼잡도: 샘플" 확대 | LLM은 숫자를 안 만든다 |
| 55–60 | "이걸로 예약해줘" → vooy 확인 화면 직전에서 멈춤 | 다음은 vooy의 손 |

### 동선 B — 텍스트 + 링크 보드 (기본)

- 0–20초: 동선 A와 같음(연결 장면은 "서비스 연결 화면에 https 주소 한 줄")
- 20–30초: vooy가 텍스트로 3안(시간표·사람별 %)을 답하고 보드 링크를 보냄 → 링크를 탭하면 폰 브라우저에서 같은 보드가 열림
- 30–42초: 링크 보드에서 저울·양보 조작(우리 REST로 같은 솔버 호출)
- 단톡방 호출이 안 되면: 1:1 대화에서 "민지는 이렇게, 지훈은 이렇게 말했어"로 같은 흐름

## 7. 구현 메모 (컨셉 확정 뒤 PRD로 옮길 것)

- 스택: Python `mcp` SDK의 FastMCP(uv로 설치). `stateless_http=True`, `json_response=True`. 공개는 ngrok. `--stdio`는 로컬 테스트용 선택 옵션
- 레시피 초안(제출물): "여러 사람이 같이 나들이·여행 코스를 정하는데 각자 조건(꼭 가고 싶은 곳, 걷기, 시간, 예산)이 다를 때 `propose_plans`를 부른다. 각자 한 말을 `wants`로 옮기고, 옮기지 못한 말은 `unmapped`에 그대로 넣는다. 결과의 3안과 사람별 %를 그대로 보여 주고, 숫자를 만들거나 바꾸지 않는다. 누가 양보하겠다고 하면 `adjust_plan`, 안 된다고 나오면 `explain_infeasible`." + 예시 대화 2개(§4.1 시나리오, 조건 충돌 시나리오)
- 도구 결과의 `content[0].text`는 그대로 메신저에 붙여도 읽히게 쓴다(완료 기준이 "결과가 대화로 돌아옴")

### 7.1 구현 방식: Codex 위임 (상위 폴더 `CODEX_DELEGATION.md`)

이 세션은 PRD·브리프·리뷰만 하고, 코드는 `codex exec`로 맡긴다. 브리프는 `vooy-mcp/codex/NN_이름.md`, 결과는 `NN_이름.result.md`. 사용자가 구현 시작을 승인한 뒤에 진행한다.

| # | 브리프 | 모델 / effort | 완료 기준 |
|---|---|---|---|
| 01 | 원격 MCP 서버 뼈대 + `propose_plans` (Streamable HTTP, stateless·JSON 응답, 솔버 import, 텍스트 결과) | `gpt-6-astra` / high | MCP 클라이언트 스크립트로 `initialize → tools/list → tools/call propose_plans`가 3안 텍스트를 돌려줌 |
| 02 | `adjust_plan`, `explain_infeasible`, `find_candidates`(MRT 공개 MCP 실호출 + 샘플 표기) | `gpt-6-astra` / high | 같은 스크립트로 양보·불가능 시나리오 통과 |
| 03 | 링크 보드 `/b/{id}` (벤토 HTML, 저울·양보 버튼 → `/api/adjust`) | `gpt-6.1-sol` / medium | 브라우저에서 저울 조작 시 막대가 바뀜(스크린샷) |
| 04 | 레시피 문서(지침 + 예시 대화 2개), README(실행·ngrok·vooy 등록 순서) | `gpt-6.1-sol` / medium | Recipe Studio에 그대로 붙일 수 있는 텍스트 |

- 환경: `tripfit/.venv`에는 `mcp` SDK가 없다(2026-11-07 확인). 메인 트랙 환경을 바꾸지 않도록 **`vooy-mcp/.venv`를 uv로 따로 만든다**(mip 1.16rc0 + mcp + python-dotenv). 별도 프로젝트로 내기로 해서 솔버는 `tripfit/solver/`에서 `vooy-mcp/` 안으로 복사해 쓴다(원본은 그대로)
- 건드리지 않는 곳: `tripfit/`(특히 메인 트랙 Codex가 만드는 `tripfit/server/`), `skt-agentic-pay/`, `fnf-vmd/`
- 비밀값은 상위 폴더 `.env`에서만 읽는다. 이 서버는 기본적으로 키가 필요 없다(MRT 공개 MCP는 인증 없음)
- MCP Apps: 도구 `_meta.ui.resourceUri = "ui://hapui/board"`, 리소스 MIME `text/html;profile=mcp-app`. 위젯 JS는 ext-apps 브리지로 `adjust_plan` 호출. FastMCP의 tool `meta` 인자와 리소스 MIME 지정 지원 여부는 설치 버전에서 먼저 확인
- 같은 HTML을 `GET /b/{problem_id}`로도 서빙하고, 위젯에서 브리지가 없으면 `fetch('/api/adjust')`로 전환(한 파일, 두 경로)
- 인증: 기본 없음(데모), `MCP_TOKEN` 환경변수가 있으면 Bearer 검사. 주소는 외부에 공유하지 않는다
- stdout: 솔버 호출은 `_quiet_native_stdout` 안에서만. stdio 모드 로그는 stderr
- 파일은 모두 `vooy-mcp/` 아래. `tripfit/solver`는 `sys.path`로 import만 하고 고치지 않는다
- 도구 설명에 한국어 예문 5개씩, 영어 한 줄(vooy 도구 검색이 한·영·일 예문으로 색인)
