# 11 — 결제 승인 화면의 "AI 슬롭" 걷어내기 (web/pay/만)

사용자 평: 흐름은 완전히 마음에 드는데, 4단계 "이대로 승인해도 되는 이유" 화면이 AI가 만든 티가 난다. TripFit 4단계 시트 안 iframe(`pay/?embed=1`, 폭 약 380px)에서 본 모습 기준으로 고친다. `web/pay/app.js`, `styles.css`, `index.html`만 수정. 엔진(`web/pay/engine/`)·검사 로직·데이터는 그대로.

## 고칠 것

1. **똑같은 민트 상자 6개 격자 → 한 장의 확인서(목록)**. 은행 이체 확인 화면처럼 흰(크림 `#F3F1EA` 계열 기존 색) 블록 하나 안에 6줄. 각 줄: 왼쪽 작은 라벨(판매처/상품/금액/예약/기한/위임), 오른쪽 사람 말투 값 + 맨 끝 작은 라임 원 체크(실패면 red 원 X). 줄 사이 얇은 점선. 예:
   - 판매처 — 마이리얼트립 · 맡긴 곳 그대로
   - 상품 — 서울숲 숲체험 11월 14일 15:00 · 합의한 일정 그대로
   - 금액 — 1인 35,000원 · 맡긴 한도 안 (`≤` 같은 기호 쓰지 말 것)
   - 예약 — 15:00 자리 있음 · 14:41에 다시 확인
   - 기한 — 16:50까지 · 2시간 남음 (초 단위 카운트다운 제거, 분 단위)
   - 위임 — 지민·서연 각 1회 · 아직 안 씀
   값은 지금처럼 엔진 결과에서 만든다(하드코딩 금지).
2. **"맡긴 조건 모두 확인 6/6 통과" 블록 + "맡길 때와 달라진 것" 블록을 합친다** → 확인서 맨 위 한 줄 제목 "6가지 모두 맞아요"와 그 아래 작은 줄 "맡길 때와 달라진 것 없음". 달라졌으면 그 줄이 red로 `35,000원 → 38,000원`.
3. **embed 모드 헤더 정리**: 바깥 시트가 이미 "예약하고 결제하기"를 보여 주므로, `?embed=1`에서는 "TripFit · 같이 결제" 줄을 숨기고 단계 번호(04/05)만 진행 막대 옆 작게. 라임 제목 블록 높이를 줄인다(제목 2줄 + 진행 막대, 설명 문장 1줄은 유지 가능).
4. **눈썹 라벨 띄어쓰기**: "결제전확인" → "결제 전 확인", "결제맡기기" → "결제 맡기기", "예약확인" → "예약 확인", "결제완료" → "결제 완료". 모든 단계.
5. **스크롤바 숨김**: 스크롤은 되되 막대는 안 보이게(`scrollbar-width: none`, `::-webkit-scrollbar{display:none}`), embed·단독 둘 다.
6. 같은 "균일한 상자 격자" 패턴이 다른 단계에 있으면 같은 원칙(한 블록 안 목록)으로 정리. 카드 금액(pink/sky)·합계(navy 라임 숫자)·"누르면 일어나는 일"은 유지.
7. 줄바꿈 고아 방지: 값 텍스트가 2줄이 되면 `text-wrap: balance`.
