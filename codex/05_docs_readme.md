너는 `tripfit/` 폴더에서 일한다. 이 저장소는 해커톤 제출물이다. **스폰서 트랙은 무대 시연 없이 GitHub와 데모 링크만 보고 고르고, 채점을 AI가 할 가능성이 높다.** 그래서 README 하나만 읽어도 무엇을 만들었고, 어디까지 실제로 동작하며, 어떻게 확인하는지가 근거와 함께 드러나야 한다. 먼저 `README.md`, `README_RUN.md`, `PRD.md`, `SCREENS.md`, `codex/03_mrt_live.result.md`, `codex/04_whatif_concession.result.md`, `web/demo_data.js`(숫자 원천), `solver/tripfit_solver.py`, `solver/sample_seongsu.py`, `server/app.py`를 읽어라.

## 1. README.md 다시 쓰기 (한국어)

순서와 내용:

1. **제목 + 한 줄**: "두 사람이 각자 한 문장씩 말하면, 둘 다 납득하는 반나절 일정을 수학으로 짜 주는 여행 합의 앱"
2. **스크린샷**: `docs/screens/`의 이미지(총괄이 넣는다: `01-chat.png`, `02-plans.png`, `03-concession.png`, `04-agree.png`, `05-replan.png`)를 표 또는 나란히 배치. 파일이 아직 없어도 경로대로 써라.
3. **30초 요약**: 문제(동행 여행에서 "아무거나"와 눈치 보기) → 해법(말 → 체크리스트 → MIP가 파레토 일정, 서로의 만족도를 숫자로) → 와우 장면 3개(① "이 말은 양보할게" 한 번에 저울이 다시 계산 ② 실상품을 넣으면 "지금은 안 되고, 누가 무엇을 양보하면 된다"를 계산 ③ 여행 중 붐비면 예약은 지키고 나머지만 다시 짬).
4. **심사 항목별 근거 표** (이 저장소에서 확인할 수 있는 파일·명령·숫자로만): 기술적 완성도 / 상업적 가능성 / 팀 실행력 / 스폰서 리소스 활용 / API 활용도 / 창의성·시도 / 빌더 임팩트. 각 행에 "근거"와 "확인 방법(파일 경로 또는 명령)". 예: 테스트 수(솔버 8, 서버 35 통과 1 skip — 실제 실행해 숫자 확인), 솔버 계산 시간(로그의 ms), 실호출 API 목록.
5. **3분 안에 직접 돌려 보기**: 설치·실행 명령, 키 없이도 되는 것(재생 모드 `web/index.html` 열기, 키보드 → ← 1~6 A C H E R), 키가 있으면 되는 것. 테스트 명령.
6. **어떻게 동작하나**: 데이터 흐름 그림(텍스트 다이어그램): 문장 → LLM(OpenAI gpt-6.1-sol, JSON) → Constraint JSON → Python-MIP(CBC) 시간창 오리엔티어링 → 파레토 대안·what-if·재계산 → 화면. "LLM은 숫자를 만들지 않는다" 원칙.
7. **점수 로직**: 사람 만족도 = 그 사람이 한 말의 체크리스트 충족률(강도 strong 1.0/normal 0.7/weak 0.4, 종류 visit/dwell/walk/stops의 선형식), 장소 점수 Q = 0.4 고유성 + 0.3 평판(베이지안) + 0.3 시간대 혼잡. 수식은 짧게, 상세는 PRD §6.3 링크.
8. **실호출 / 샘플 표**: 지금 README 표를 갱신(마이리얼트립 MCP 실호출 스냅숏, OpenAI 실호출, 성수 장소·혼잡도는 샘플, 도보는 직선×1.3 추정, 결제는 아래 SKT 절).
9. **스폰서 트랙** 절 두 개 — 내용은 총괄이 통합 때 채우므로 지금은 뼈대와 TODO 주석만:

   - 마이리얼트립(메인 안의 스폰서 리소스 활용)은 지금 내용으로 따로 짧은 절.
10. **한계와 정직한 표기**: 추정값(좌표·소요시간·도보), 샘플 데이터, 임의 문장 → 일정 세션 미지원 등.
11. **저장소 구조**(트리, 주요 파일 한 줄 설명), **문서 링크**(PRD, SCREENS, README_RUN), **출처·라이선스**(서울미래유산 공공누리 1유형, 마이리얼트립 MCP, 솔버는 행사 전 공개한 개인 알고리즘을 확장 — 오늘 추가한 것 목록: 체크리스트 만족도, 장소 점수, 양보안 계산, MRT 연동, 서버·화면).

문체: 짧은 문장, 번역체·과장 금지("혁신적", "획기적" 금지), 이모지 금지. 표와 코드 블록 적극 사용. 600줄 넘기지 말 것.

## 2. PRD.md·SCREENS.md 숫자와 장면 갱신

- PRD §4(사용자 흐름), §6.1(실제 상태 표), §6.4, §6.5(마이리얼트립 실상품), §11(성공 지표), §12(1분 피치), §13(Q&A: "체험은 진짜 상품인가", "왜 못 넣는다고 나오나", "양보는 어떻게 계산하나" 추가), 부록 A(저장소 구조).
- SCREENS.md: 3단계를 "가상 공방 16:00 → −8" 대신 "숲체험 15:00 → 불가능 → 양보안 버튼 → 서연 카페 양보 → 4곳 빠짐"으로, 5단계를 "숲체험 15:00 유지, 디뮤지엄 → 대림창고"로. "공방", "16:00", "가죽" 흔적을 모두 찾아 고쳐라(`grep -n "공방\|16:00\|가죽"`).
- `web/index.html`의 `CAPS`(피치 대본)와 PRD §12 대본이 같은 문장인지 확인하고, 다르면 PRD를 CAPS에 맞춰라.
