# 10 — SKT "같이 결제" 화면을 TripFit 품질로 다시 그리기 + "이대로 승인해도 되는 이유"

너는 `tripfit/` 폴더에서 일한다. `web/pay/`(SKT 트랙 화면: `index.html`, `app.js`, `styles.css`, `api.js`, `engine/`, `data/`)는 로직은 탄탄하지만(엔진 테스트 25개) **화면이 TripFit 본 화면(`web/index.html`)보다 품질이 떨어져 보인다**: 베이지 바탕의 데스크톱 폼 레이아웃, 기본 탭, 얇은 글씨, 비어 있는 어두운 패널, 개발용 표(실호출·목업 표기, 테스트 버튼)가 본문에 노출. 게다가 TripFit 4단계에서 **폰 프레임 안 iframe(`pay/?embed=1`, 폭 약 393px)**으로 열린다. SKT 심사자는 이 화면 하나로 "에이전트에게 결제를 맡겨도 되는가"를 판단한다.

먼저 읽어라: `agentic-pay/README.md`, `web/pay/` 전체, `web/index.html`의 `<style>`(토큰·블록·노치·폰트·스프링·아일랜드·`fitNumber`), `docs/screens/*.png`(TripFit 화면), `agentic-pay/docs/screens/*.png`(현재 결제 화면).

## 디자인: TripFit과 같은 앱처럼

- 토큰을 그대로: navy `#0E2A3A`, lime `#D6F23B`, mint, pink(지민 `#FFCCE5`), sky(서연 `#8EC5EE`), peach, butter, violet, lilac, red. 숫자 Inter Tight, 한글 Pretendard(같은 CDN). 블록 라운드·노치(`.cut`/`.tab`), 블록 사이 4px navy 간격, 스프링 `linear()` 곡선. `web/index.html`에서 필요한 CSS를 `web/pay/styles.css`로 옮겨 써라(공유 파일을 새로 만들어도 됨, 단 `web/index.html`은 고치지 마라 — 다른 작업이 동시에 고친다).
- **모바일 우선 한 열**(최대 430px). `?embed=1`이면 iframe 전체를 앱 화면처럼 채우고 상단 제목·바깥 여백 없음. 단독(`/pay/`)으로 열면 TripFit 데스크톱처럼 민트 배경 가운데 폰 폭 열 + 왼쪽에 짧은 설명 캡션(SKT 과제 한 줄, 단계 n/5).
- 단계 표시: 상단 라임 블록에 단계 제목(큰 한글, 자간 -0.05em) + TripFit 캡션과 같은 진행 막대. 기본 탭 UI 제거.
- 이모지 금지, 회색 흐린 글씨 금지(대비 4.5:1), 빈 패널 금지.

## 단계별 화면

1. **일정 확인** — 합의 일정의 장소 블록(TripFit 일정 카드와 같은 모양), 결제할 항목(서울숲 숲체험 15:00)은 violet 해칭 블록으로 강조, "이번에 결제할 것 1개 · 현장 결제 2곳".
2. **결제 맡기기(위임)** — 지민(pink)·서연(sky) 블록 각각: 판매처·상품·옵션·1인 상한·기한·1회. 큰 숫자 "35,000원까지". 승인은 **길게 누르기 버튼에 원형 진행 링**(라임, 1초). 승인되면 블록에 체크 도장 애니메이션.
3. **예약 확인(에이전트가 대신)** — 에이전트 활동 타임라인(아일랜드 문법의 알림이 위에서 내려옴): "마이리얼트립에 15:00 다시 조회 중" → 결과 큰 숫자 "15:00 예약 가능 · 35,000원", 출처 알약(`실시간 조회 HH:MM` 또는 `저장된 조회 결과 HH:MM`), 판매자 문의 초안은 접힌 카드.
4. **결제 전 확인 = "이대로 승인해도 되는 이유"** (이 화면이 핵심)
   - **검사 6개 체크 그리드**(엔진이 실제로 계산한 결과를 그대로 표시, 하드코딩 금지): 판매처 일치(마이리얼트립 = 맡긴 판매처) · 상품·시각 일치(서울숲 숲체험 15:00 = 합의 일정) · 가격 ≤ 상한(35,000 ≤ 35,000, 사람별) · 예약 가능(조회 시각) · 기한 안(남은 시간) · 두 사람 위임 완료·1회 미사용. 각 칸에 근거 한 줄. 하나라도 실패면 red 블록 + 결제 버튼 잠금 + 무엇을 해야 하는지(예: "새 금액으로 다시 맡기기").
   - **맡길 때와 달라진 것**: 없으면 "달라진 것 없음", 가격 인상 테스트면 `35,000 → 38,000` 나란히 + 재위임 버튼(엔진의 기존 흐름).
   - **누르면 일어나는 일** 3줄: 지민 카드 35,000원 · 서연 카드 35,000원이 각각 1회용 결제 권한으로 결제 / 판매자도 같은 승인 기록(해시 앞 8자) 수신 / 모의 결제 — 실제 돈은 나가지 않음.
   - 분담 금액: pink·sky 블록에 큰 숫자(Inter Tight), 합계는 navy 블록의 라임 숫자 70,000(`fitNumber` 문법으로 넘침 방지).
   - 결제 버튼: 길게 누르기 링. 누가 누르는지 표기("대표 지민이 두 사람 위임으로 결제").
5. **결제 완료(영수증)** — 영수증 블록(톱니 하단 유지 가능): 승인번호, 사람별 금액, 기록 해시(앞 8자 + 복사), 판매자에게 전달된 내용, 예약 확정은 마이리얼트립 링크 버튼(알약). "다른 판매처 결제 시도 → 거절(MERCHANT_MISMATCH)" 테스트 결과는 red 블록으로 "에이전트가 막은 것".
- **기술 정보** 토글(맨 아래 작은 알약): 실호출/목업 표, 감사 로그(해시 체인), 테스트 버튼(가격 인상, 다른 판매처). 본문에는 노출하지 않는다.

## 규칙

- **엔진(`web/pay/engine/`) 동작·공개 함수 변경 금지.** 렌더링(`app.js`, `index.html`, `styles.css`)만 바꾼다. 상태 흐름·API 호출(`api.js`, `/api/pay/recheck` 실패 시 저장값 폴백)·`window.TRIPFIT_PAY_INPUT` 입력 지원 유지.
- `web/index.html`, `server/`, `solver/` 수정 금지.
- 완료 기준: `(cd agentic-pay && node --test test/*.test.mjs)` 25개 통과, `.venv/bin/python -m pytest server/test_pay_router.py -q` 12개 통과, `node --check web/pay/app.js`. Playwright가 되면 390×844(`?embed=1`)·1440×900(단독)에서 정상·가격 인상·다른 판매처 세 흐름 스크린샷을 `codex/10_shots/`에, 안 되면 이유 기록. 그 다음 `agentic-pay/README.md`의 스크린샷 표가 가리키는 파일을 새 화면으로 바꿀 수 있게 파일명 목록을 남겨라(교체는 총괄이 함).

## 마지막 메시지 형식

바뀐 파일, 단계별 바뀐 점, 4단계 검사 6개가 엔진의 어떤 값에서 오는지 표, 테스트 결과, 스크린샷 경로, 확인 못 한 것.
